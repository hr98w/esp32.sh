# 项目与设备的 Markdown 内容记录

记录日期：2026-10-16。用户已明确：每个开源项目和每台设备分别对应一个独立 Markdown 文件；框架已选择 TanStack Start（React），部署目标为 Cloudflare。

项目记录保存 GitHub 链接、简介等资料；设备记录保存型号、设备简介等资料。网站在构建或部署流程中自动读取这些文件，生成目录、筛选数据和页面。新增内容通过添加新文件完成，不依赖人工维护一份汇总清单。

## 文件与内容的关系

用户进一步明确：设备按厂商分文件夹。项目暂按平铺组织，分类和标签写进各项目文件，避免类别调整时移动文件。以下作为当前目录约定，具体元数据字段后续再定：

```text
content/
├─ projects/
│  ├─ project-a.md
│  └─ project-b.md
└─ devices/
   ├─ m5stack/
   │  ├─ stopwatch.md
   │  └─ cardputer.md
   ├─ waveshare/
   │  └─ esp32-s3-touch-amoled-1-8.md
   └─ lilygo/
      └─ t-display-s3.md
```

每份文件是一条完整记录。项目与设备的名称、描述、图片、标签等由各自记录承载；中文、英文和日语内容共用同一条记录和身份，避免按语言复制仓库地址或设备关系。字段和正文怎样分配，后续再定。

厂商文件夹采用统一、稳定的名称，例如 `m5stack`、`waveshare`、`lilygo`，页面可显示其正式品牌名。设备 ID 独立于厂商文件夹路径，并在设备记录范围内保持唯一。

## 项目记录

预期信息包括稳定项目 ID、名称、GitHub 仓库地址、简介、分类、关联设备 ID，可按需补充作者、图片、许可证和其他来源链接。首版点击项目直接去 GitHub；未来独立项目页面复用同一文件中的资料。

每个仓库只对应一个项目记录。支持多个设备时，通过设备 ID 列表建立关系，不把同一仓库复制成多个项目文件。

### 项目封面

封面不是必填。用户提出未填写时可自动从 GitHub 获取图片，或在封面区域显示项目名称。

建议的展示顺序为：手动指定封面 → README 中第一张通过基本筛选的图片 → 项目名称文字封面。自动筛选应跳过明显的徽章、状态条和小图标；不能保证选出的图片就是项目实物或截图，允许手动覆盖并关闭自动取图。

自动取图建议在收录或内容更新任务中完成，保存结果与来源；访问页面时使用已有结果。缺图、抓取失败或图片加载失败时显示统一风格的项目名称封面，不影响项目展示。自动取图的具体算法、缓存存储和刷新方式尚未实现或确定。

项目分类不体现在文件夹路径中。一个项目允许多个标签；新增、删除、改名或合并标签时修改元数据，目录和筛选项从现有标签自动汇总。标签不参与项目 ID、文件名或未来页面地址的生成。首版标签命名、是否区分项目类型和用途标签，留待内容整理时细化。

## 设备记录

预期信息包括稳定设备 ID、标准型号、厂商、芯片、简介、主要板载功能和官方资料链接。图片、型号别名、硬件版本、参考价格及其来源和记录时间可按需补充。

首版从设备文件生成每台设备的独立页面；相关项目列表根据项目文件中的设备 ID 关联得到，避免在两边各维护一份手工列表。

## 协作与迁移原则

- 提交新项目或设备时新增独立文件，减少多人修改同一汇总文件造成的冲突。
- 同一条记录的同时修改仍可能冲突；同一仓库重复投稿也仍需去重。
- 项目和设备分别具有稳定 ID，名称或文件路径调整不应改变身份。
- 项目引用设备 ID，不用显示名称或模糊型号作为关联键。
- GitHub 仓库地址用于项目去重；支持仓库改名后的资料修正。
- 将 Star 等自动刷新的数据与人工维护的内容分开考虑，避免定时刷新反复改动投稿文件。具体存储方式后续确定。
- 从元数据读取到的分类、厂商列表和统计自动汇总，投稿者不必同步修改全局索引。

以后迁移到数据库时，项目文件可映射为项目记录，设备文件可映射为设备记录，ID 引用可转换成项目与设备的关联表。是否能直接导入取决于后续字段约定，因此现在保留稳定身份、清晰字段和一致关联即可；独立文件本身不自动保证无成本迁移。

已实现第一版内容读取：YAML Frontmatter + Zod 校验，在 Node 构建阶段生成 `src/generated/catalog.json`，应用读取生成数据，Cloudflare 运行时不访问原始文件系统。开发服务器监听 Markdown 变化。字段定义见 `src/lib/content/schema.ts`，投稿模板位于 `templates/`；具体字段仍可调整。

当前已有 2 个真实项目与 2 个设备作为结构样例，项目文件平铺、设备按厂商分目录，界面和简介支持中英日。许可字段检查不能代替人工核实许可证，适配关联仅代表上游声明，不代表本站实测。独立 HTML Demo 保留在 `docs/prototype/`，并未整体迁移。GitHub 自动取图、Star 采集、投稿自动化与数据库尚未实现，网站尚未部署。

## 首轮实现状态

当前已接通独立 Markdown、三个语言摘要、来源与核验时间、Star 快照、README 图片候选，以及设备关联的反向查询。Star 和自动图片在 `data/` 保存，构建时合并，人工内容文件不随快照更新改写。README 图片按顺序跳过明显徽章、Logo、状态图，手动封面与关闭自动取图仍优先；图片不可用时显示项目名，包括在客户端初始化前已失败的图片。

采集与合格入库分开：目录候选、上游核验、编辑摘要和明确的型号关联各自保留状态。详细字段以 `src/lib/content/schema.ts` 为准，实际进度以生成的采集报告为准。当前没有 AI 自动审核或自动发布流程。
