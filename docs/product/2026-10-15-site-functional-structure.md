# esp32.sh 网站功能结构草案

记录日期：2026-10-15。更新日期：2026-10-16。状态：主页 HTML 原型已由用户检查，框架已选择 TanStack Start（React），部署目标为 Cloudflare；已建立本地应用骨架与 Markdown 读取，完整页面功能继续开发，尚未部署。

esp32.sh 是中英日多语言的 ESP32 开源项目与设备目录，核心任务是让用户根据手里已有的具体设备找到有意思的开源项目；也支持先发现项目，再了解相关设备。

以 [M5Ware](https://m5ware.com/) 的项目目录、设备筛选和热度浏览为主要参考，结合 [ESPboards](https://www.espboards.dev/esp32/) 的厂商、芯片和硬件分类。项目介绍保持简短，AI 根据原仓库整理描述，制作细节由上游项目承载。

## 导航与页面关系

首版去掉“合集”和“收藏”，顶部导航保留项目、设备，提交 / 纠错、语言下拉框和 GitHub 作为辅助入口。厂商与芯片是设备目录中的浏览维度，拥有独立聚合页，不必占据顶部导航。

```text
esp32.sh
├─ 项目：同时作为首页
│  ├─ 搜索、选择设备、分类、排序
│  ├─ 项目列表
│  ├─ 首版点击项目 → GitHub 仓库
│  └─ 后续每个项目有独立站内页面
├─ 设备
│  ├─ 设备列表
│  ├─ 厂商聚合页
│  ├─ 芯片聚合页
│  └─ 每台设备的独立页面 → 该设备的开源项目（首版提供）
├─ 提交
│  ├─ 推荐项目
│  ├─ 添加设备
│  └─ 纠错与补充设备关联
└─ 页脚：关于、收录规则、数据来源、GitHub
```

## 首页与项目目录

首页直接展示项目目录，提供简短定位与搜索控件后进入内容。优先让用户浏览项目、选择自己的设备。

界面保留 Windows 风格的窗口边框、深蓝标题栏和简洁立体控件；移除模拟系统菜单、地址栏、任务栏、窗口控制按钮以及卡片/列表切换等额外入口。仅项目目录展示设备筛选侧边栏，替换顶部设备下拉框；设备目录用顶部厂商、芯片及功能筛选，独立设备页集中展示设备资料与相关项目。设备目录、设备详情与未来项目详情页保持全宽。

最突出的操作是“选择我的设备”。侧边栏支持搜索完整型号、简称、别名和厂商，按厂商折叠分组，型号旁展示已关联项目数。默认只展开少量厂商，搜索时展开匹配结果；只列出已有项目关联的设备，并保留设备目录入口。手机端收为“选择设备”按钮，打开后搜索或选择。例如用户选择 M5Stack StopWatch 后，目录标题及结果都明确限定到该设备。

首版每次选择一个具体设备。筛选状态体现在 URL 中，切换排序或语言时保留选择，可直接分享“这台设备能玩的项目”。设备尚未收录或没有已知项目时说明当前收录情况，并提供补充入口；不把相同芯片的项目自动算入精确匹配结果。

| 控件 | 建议内容 |
| --- | --- |
| 搜索 | 项目名、用途描述、作者；搜索建议同时提供设备入口 |
| 具体设备 | 核心筛选，支持型号与别名搜索 |
| 项目类型 | 应用与固件、游戏、工具、库与框架 |
| 用途标签 | AI 与语音、桌面与显示、智能家居、游戏与玩具、音乐、机器人等；按实际内容建立 |
| 更多筛选 | 厂商、芯片、开发框架；随数据覆盖逐步增加 |
| 排序 | 默认总 Star；另提供新收录、最近更新 |

类型描述“项目是什么”，用途描述“项目做什么”，两者分别维护。无需因为一个项目使用某框架，就把它归入框架类。

最近更新建议按仓库最近代码提交时间定义，数据来自提交信息；目录收录时间单独记录，不混用仓库创建时间、最近推送时间或网站资料刷新时间。总 Star 和相关元数据允许定时刷新，展示数据更新时间，不承诺实时。

首版不依赖 Star 增长趋势；若以后增加周榜，需要保存历史快照。

项目卡片包括名称、作者、短描述、用途标签、支持设备、Star 和仓库链接；有合适素材时展示封面或 demo 预览。许可证和更新时间可用紧凑元数据呈现。用户已明确：首版点击项目卡片、名称或主操作入口，直接打开对应 GitHub 仓库。设备标签继续用于筛选或设备导航；首版不提供收藏按钮或本地收藏功能。

每个项目从首版就保留稳定标识、slug 和独立的仓库地址字段。跳转目标与项目身份分开，后续增加站内项目页时复用已有项目记录及设备关联。是否默认转为打开站内页，在该阶段决定；原仓库入口继续保留。

## 后续独立项目页面

独立项目页面是用户明确希望后续提供的功能，不纳入首版。每个已收录项目都有自己的页面，以下内容是该阶段的建议：

- 项目名称、作者、封面或 demo。
- AI 整理的多语言短描述，约两三句话，说明主要功能。
- 支持的具体设备，点击进入设备页；通用项目可以只标芯片系列。
- 仓库 Star、许可证、最近代码提交时间和资料刷新时间。
- 原仓库、作者 demo、官方文档等原始入口。
- 相同设备或相近用途的其他项目。
- GitHub 纠错入口。

设备关联必须有原项目支持列表、构建配置或明确社区报告等依据；AI 提取事实并保留来源，不能仅因同用一个芯片就推断整台设备兼容。对用户只需简短说明支持依据，有必要时标明硬件版本。

首版不把材料清单、接线、安装步骤、制作时间或完整教程设为项目必填字段。原 README 直接链接到上游，不整体复制到本站维护。

只收录具有明确开源许可的项目。缺少明确许可或许可不符合收录标准的条目进入待确认流程，不直接发布为开源项目。一个仓库支持多款设备时共用一个项目记录，避免重复计算 Star。

## 设备目录与厂商入口

对用户统一称为“设备”，涵盖 Espressif 原厂开发板、第三方通用板、集成屏幕或麦克风等外设的一体板，以及带外壳的成品设备。硬件设计是否开放单独记录，不将其与软件项目的开源许可混为一谈。

| 筛选维度 | 示例 |
| --- | --- |
| 厂商 | Espressif、M5Stack、Waveshare、LILYGO、Seeed 等 |
| 芯片系列 | ESP32、ESP32-S3、ESP32-C3、ESP32-C6 等，依实际收录扩展 |
| 板载功能 | 显示屏、触摸、电子纸、麦克风、扬声器、摄像头、IMU、LoRa 等 |
| 产品形态 | 通用开发板、显示设备、手持或穿戴设备、其他集成设备 |
| 价格范围 | 仅在已有参考价的数据上筛选；缺价设备不消失 |

板载功能支持同时筛选多个条件，例如“屏幕 + 麦克风”。不要把产品形态、芯片或用途写进同一个混杂标签字段。

设备卡片展示图片、标准型号、厂商、芯片、关键板载功能、参考价格和相关项目数。优先按相关项目数或名称提供排序；项目数表示目录关联数量，不等于设备销量或受欢迎程度。

首版点击设备卡片或设备名称进入该设备的独立站内页面。项目目录中的型号选择仍承担筛选任务，与进入设备页面的操作区分。

厂商页提供简短介绍、旗下设备及对应项目入口。芯片页提供简短系列说明和所收录设备；详细数据手册链接官方来源。两者复用同一份设备记录。

型号别名可帮助搜索，硬件版本有实质差异时应保留区别。同一商品的改名不重复建档；同系列不同尺寸屏幕、不同硬件配置不能仅因名称接近而合并支持关系。

## 具体设备页

用户已明确：首版每个收录设备都有自己的独立站内页面和稳定地址。无需等待独立项目页建设完成。

页面开头展示型号、图片和短介绍，紧接着突出“这台设备能玩什么”。相关项目列表可以继续按 Star、新收录或最近更新排序。

设备页中的项目卡片和标题在首版直接打开对应 GitHub 仓库，与首页项目卡片保持一致。

页面后续提供厂商、芯片、主要板载功能、必要规格、参考价格、官方产品页和文档入口。价格附币种、来源和记录时间；国内与海外价格有来源才分别记录，允许缺省。

若设备有需要区分的硬件版本，相关项目按已知版本标注。没有关联项目也可保留设备资料页，明确当前尚未收录对应项目，并提供投稿入口。

相似设备可以作为补充入口；相似外观、芯片或功能不构成项目兼容性证明。

## 后续可选的合集与选购

用户已接受首版去掉合集，主题发现先由分类、标签及设备筛选承接。以后如有需要，可讨论少量人工定题、复用现有数据的合集，例如桌面电子宠物、电子纸项目或适合语音项目的设备。

项目合集引用项目记录，选购合集引用设备记录并附简短选择理由和参考价格。以已有项目数量和资料支撑选题，不预设每日更新节奏。

## 投稿与低维护流程

用户可通过 GitHub Issue 表单贴项目或设备链接，也可直接修改内容文件提 PR。首版可从目录及设备页进入纠错；后续独立项目页提供预填当前项目的纠错入口。

建议流程为 GitHub 提交、规则检查、AI 整理多语言短描述及关联来源、生成预览、合并后自动部署。规则稳定前保留人工合并；后续是否自动合并另行决定。

格式校验、仓库去重、许可识别、元数据刷新和失效链接检查由自动化处理。AI 用于内容变更的整理，不必每次刷新 Star 都重写描述。对外部接口暂时失败保留已有数据，避免误删条目。

用户已明确：每个项目、每台设备各使用一个独立 Markdown 文件，新增投稿通过添加新文件完成；网站在构建或部署时自动读取文件并汇总目录、筛选数据及页面。项目使用稳定设备 ID 建立多对多关系，不需要人工同步维护两份关联列表。这种内容组织可支持无数据库首版，并为未来数据库迁移保留清晰记录与关联。Star 等自动刷新数据与人工内容分开考虑，具体存储方式待定。框架已选择 TanStack Start（React），部署目标为 Cloudflare；已用 YAML Frontmatter + Zod 建立首个可运行内容约定，构建阶段生成目录数据，具体字段仍可调整。详见 [Markdown 内容记录](2026-10-16-content-records.md)。

## 多语言与页面地址

语言选择使用下拉框，提供中文、English、日本語。中英文同等重要，日语覆盖导航、筛选、内容简介与辅助说明。切换语言保留设备、分类、搜索与排序；各语言共用内容身份。


各语言提供同等导航和功能。项目和设备的标准身份、仓库地址、Star、价格及关联事实共用，标题、简介和说明分别本地化；型号不翻译。

默认英文使用无语言前缀路径（`/`、`/devices` 等），中文使用 `/zh`，日语使用 `/ja`。旧 `/en/...` 地址重定向至无前缀英文地址。切换语言保留当前页面与筛选。下表列出中文路径示例：

| 页面 | 中文路径示例 |
| --- | --- |
| 首页项目目录 | `/zh/` |
| 后续独立项目页 | `/zh/projects/<slug>/`，首版只预留 slug，不生成页面 |
| 设备目录 | `/zh/devices/` |
| 每台设备的独立页面 | `/zh/devices/<slug>/`，首版提供 |
| 厂商 | `/zh/manufacturers/<slug>/` |
| 芯片 | `/zh/chips/<slug>/` |
| 投稿 | `/zh/submit/` |

切换语言时尽量保留当前条目和筛选状态。分类聚合页只在有实质内容时建立，任意筛选组合不自动生成大量重复的索引页面。

## 首版范围

首版优先包含项目目录及型号筛选、项目点击直接跳转 GitHub、设备目录及每台设备的独立页面、厂商与芯片入口、中英日多语言、GitHub 投稿纠错、元数据刷新和自动部署。合集不纳入首版。后续为每个项目增加独立站内页面。

账号、评论、投票、在线 AI 对话、站内编译和直接烧录不纳入首版；以后依据实际需求决定。当前功能结构不依赖数据库或持续撰写完整教程。

既有约束见 [产品方向](2026-10-15-product-direction.md)，竞品依据见 [按设备寻找项目的现有产品](../research/2026-10-15-device-to-project-discovery.md)及 [ESPboards 结构研究](../research/2026-10-15-competitor-structure.md)。

## 首版辅助入口补充

顶部保留项目、设备两项导航；提交 / 纠错和语言下拉框作为辅助操作，页脚提供关于 / 收录说明与 GitHub。暂不增加其他核心栏目。

关于 / 收录说明以简短内容解释网站用途、明确开源许可证要求、设备适配来源，以及 Star、价格等数据的更新日期。提交 / 纠错通过 GitHub 推荐项目、添加设备或说明错误来源；项目和设备各自新增独立 Markdown 文件。搜索空结果、未找到设备和设备资料中提供补充或纠错入口。

当前 HTML 仅演示上述流程，未配置网站实际 GitHub 仓库，不发送投稿。未来接入实际仓库时，辅助入口可直接打开对应 Issues / PR 页面，不链接到无关仓库。
