# esp32.sh 产品约束与待定事项

记录日期：2026-10-15。更新日期：2026-10-16。以下区分用户已明确的方向与尚待讨论的选项，供后续设计延续使用。

## 用户已明确的方向

- 域名为 esp32.sh，网站自身开源。
- 首版以流量与内容为目标，不做付费；未来可能接入数据库、登录与支付，选型需保留扩展空间。
- 中英文同等重要；语言切换采用下拉框，新增日语支持。默认英文不带语言前缀，首页为 `/`、设备目录为 `/devices`；中文使用 `/zh`，日语使用 `/ja`。各语言共用项目、设备与筛选状态。
- 优先降低维护投入，框架已选择 TanStack Start（React），部署目标为 Cloudflare；首版倾向不使用数据库。
- 核心内容为有意思的 ESP32 开源项目；收录的项目必须开源。
- 设备从 ESPboards 等目录出发按厂商系统整理，40 台为首个里程碑；项目从现有网站或 awesome-esp32 等目录发现，60 个为首个里程碑，其他任务收敛后继续扩充。
- 维护收录与候选台账，记录待收录、待核验、已收录及排除原因；设备关联不确定时允许待定，不强行匹配。
- 项目入库需有 README，排除 Star 少于 10 的仓库，并关注内容质量。许可要求另有措辞待澄清，暂沿用必须开源的约束。
- 本轮允许调整采集字段与脚本，仅完成本地审阅，不部署或向外部提交内容。
- 最新边界：允许合理限速的匿名 GitHub 只读采集，使用不加载个人配置的 curl 等方式；禁止使用 `gh`、个人 API Key、登录 Cookie 或其他个人身份，不探测个人凭据。先离线验证采集流程，模拟夹具与正式内容隔离；仍只交付本地审阅结果。
- 每个开源项目对应一个独立 Markdown 文件，保存 GitHub 链接、简介等信息；每台设备也对应一个独立 Markdown 文件。
- 网站在构建或部署时自动读取项目和设备文件，汇总目录并生成页面；投稿新增文件，减少多人修改汇总文件的冲突。
- 项目和设备使用稳定 ID 关联，便于后续迁移到数据库；已建立可运行的初始字段约定，仍可随讨论调整。
- 设备文件按厂商分文件夹；项目文件平铺，分类和多个标签保存在文件中，允许随内容调整，不依赖分类目录。
- 项目可以由 AI 总结简短描述，不要求网站维护材料清单、完整复现说明等；详细内容引导用户访问原仓库。
- 项目封面不是必填；未填写时可尝试从 GitHub README 提取图片，缺图时在封面区域展示项目名称。自动取图细节继续讨论。
- 首版点击项目卡片或项目标题直接跳转对应 GitHub 仓库；后续每个收录项目都要有独立的站内页面。
- 项目支持按 Star 等信息排序，按具体设备型号筛选。
- 仅项目列表页展示设备筛选侧边栏：支持型号、别名与厂商搜索，按厂商折叠分组，并显示关联项目数；每次选择一个设备。手机端通过“选择设备”展开。设备目录、设备详情和未来的项目详情页不展示该侧边栏。
- 用户特别看重“根据手里已有的具体设备型号寻找开源项目”，这是后续结构设计的核心使用路径。
- 设备包括 Espressif 原厂开发板，也包括下游厂商的集成产品，例如 ESP32 加屏幕、麦克风及其他外设的板子或设备。
- 首版每个收录设备就有独立站内页面，提供设备信息及对应开源项目；与后续才建设的独立项目页区分。
- 首版去掉“合集”栏目，主题发现先通过分类、标签和设备筛选承接。
- 收藏功能暂不做：去掉收藏导航、项目收藏按钮与浏览器本地收藏逻辑。
- 设备内容可介绍型号、参考价格、用途选购及关联开源项目，具体展开程度待定。
- 首版补齐“提交 / 纠错”和页脚“关于 / 收录说明”辅助入口，包含开源许可证要求、适配来源和数据更新时间说明；空结果提供补充入口。
- 倾向 GitHub 投稿、AI 审核、自动部署，具体规则尚未确定。HTML Demo 中实际网站 GitHub 仓库尚未配置，入口明确提示待接入。
- ESPboards 与 ESPHome Devices 是重点参考对象，需保留后续流量来源与竞争研究。
- 用户已自行检查并认可主页 HTML 原型；现已建立 TanStack Start + Cloudflare 本地骨架，接通独立 Markdown、内容校验及三语言目录/设备页。完整 Demo 视觉与全部功能尚未迁移，未部署。
- 用户已指定以 M5Ware 为主要产品参考，结合 ESPboards 的设备分类组织网站功能；功能结构仍处于讨论阶段。
- 用户认可古早 Windows 的视觉方向，但要求进一步简化界面，减少模拟系统按钮与重复操作，让搜索、选设备和浏览项目更直观。

## 待讨论的结构选择

- 项目、设备和提交入口的最终导航布局；首版已排除合集与收藏。
- 首页默认展示精选、总 Star 还是新收录。
- 后续独立项目页面的具体内容，以及 AI 摘要的长度。
- 设备按厂商、芯片、板载功能、产品形态分别提供哪些筛选。
- 价格记录方式和更新频率。
- 投稿采用 Issue 表单、直接 PR，还是两者并行。
- AI 审核与人工合并的分工。
- RSS、AI 上下文复制等附加功能的范围。
- TanStack Start 在 Cloudflare 上的具体构建、预渲染与运行时部署方式；首版内容与辅助自动化的实施范围。

## 后续设计应保留的区别

项目仓库的 Star、收录日期和最后提交日期是不同信息。总 Star 可直接用于排序；趋势排序需要历史快照，不能用总量代替增长。

具体设备型号与 ESP32 芯片系列是不同层级。项目声明支持 ESP32-S3，不代表支持所有 ESP32-S3 成品板。只记录能从上游资料或贡献证据确认的关联。

“项目必须开源”不自动等同于“每台硬件的全部设计必须开源”。可将项目许可与硬件设计开放情况分别记录。项目缺少明确许可时，先列为待确认，不直接标注为开源项目。

前一轮提出的材料清单、复现时间、复杂安装说明等不作为当前必填内容要求。后续方案应按简短 AI 描述、分类与筛选、原仓库链接的轻量方向讨论。
